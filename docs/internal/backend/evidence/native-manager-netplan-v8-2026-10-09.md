# Authored Netplan automatic-policy recovery

The explicit standalone Netplan/networkd DHCPv4/SLAAC fixture passes on frozen production source
`7c99cc5d1ae58e9bf562af8d51e5911cf3bb60d5`, based on the published `d99173ef` assembly. Its actual
standalone helper advertises `jd-native-manager-v8`. This is a bounded authored-policy acceptance;
default Netplan DHCP MTU, actual DHCPv6 acquisition, structural bond/VRF editing and host reboot
remain open. The full P11 requirement remains in progress.

## Policy and recovery contract

The selected authored origin explicitly has DHCPv4 `use-mtu: false`, DHCPv4 `use-domains: true`
and RA `use-domains: true`. The inspected Netplan 1.1.2 generator emits shared `[DHCP]`
`RouteMetric=100`, `UseMTU=false` and `UseDomains=true`, plus the separate RA domain policy.
The [pinned generator](https://github.com/canonical/netplan/blob/1.1.2/src/networkd.c) writes the shared
DHCP section and separate RA overrides. The adapter verifies those settings against the exact
authored definition rather than admitting arbitrary shared networkd properties. Direct networkd
shared policy, per-protocol MTU/route/metric aliases, conflicting policy, unknown overrides and
default DHCP-provided MTU remain refused.

When a manual transition removes the generated DHCP section, the authored automatic-domain/MTU
policy remains intact. Staging and standalone recovery validate authored and generated snapshots
together for both before and candidate intent. They also compare every remaining selected property
and unselected YAML definition after removing only the represented L3 mutations. The public DTO
and private v1/v2/v3 undo vocabulary are unchanged; the existing exact file snapshots carry the
policy. Unit fixtures reject unrelated definition, renderer, identity, selected-property and
generated-policy changes before recovery effects.

Netplan's RA `use-dns` override represents DNS suppression. Its supported authored vocabulary
cannot represent IPv6 automatic-route suppression. A fresh actual fixture verifies that this
request is refused with selected source/generated bytes and inodes unchanged, no new staging or
recovery journal, and automatic acquisition still matching. The supported suppression transition
therefore retains the acquired IPv6 RA default route while suppressing automatic DNS and the IPv4
DHCP default route. Both acquired search domains remain attributable to their native protocol
even when automatic DNS is suppressed.

## Reproduction and retained records

Compile a frozen race binary from `backend/` using a workspace-local `TMPDIR`:

```bash
GOMAXPROCS=2 GOFLAGS=-p=2 go test -race -c -o ../out/netx-auto.test ./internal/netx
```

From `backend/internal/netx`, with the shared native lane clean:

```bash
timeout --kill-after=5s 240s env \
  GOMAXPROCS=2 GOFLAGS=-p=2 JD_NETNS_LIVE=1 \
  JD_NATIVE_AUTO_CASE=netplan JD_NATIVE_NETPLAN_AUTO_POLICY=explicit \
  JD_NATIVE_MANAGER_NM_ROOT=/path/to/verified/debian-NetworkManager-userland \
  /path/to/frozen/netx-auto.test \
  -test.run '^TestNativeManagerAutomaticOwnerLive$' -test.count=1 -test.timeout=235s -test.v
```

Set `TMPDIR` to a private workspace directory with enough room for the standalone helper build.
The fixture uses the already verified userland; it does not install packages. Its exact native
logs, result, cleanup and source manifest are retained in
[`native-manager-netplan-v8-2026-10-09/`](native-manager-netplan-v8-2026-10-09/).
The default all-owner automatic invocation retains the default-MTU Netplan refusal as failed
acceptance. Timer admission is stubbed in this owner-data fixture; actual timer dispatch, cold boot,
DHCPv6 acquisition and wider native-owner compatibility require their separate proofs.
