These findings were verified against the networking handlers, backend implementation and frontend.
All fixes below are included in this PR. Severity describes potential host safety, confidentiality or
reliability impact within this root-equivalent dashboard; it is not a claim that admin-only routes are
unauthenticated exploits. This review cannot establish the absence of every possible defect.

New capabilities include IPv6 policy rules with separate boot replay; route, MTU, host support,
packet snapshot and Wake-on-LAN diagnostics; an IPv6 subnet calculator; and access to the existing
IPv6 GRE/bridge-membership, route/rule and DNS fallback/cache API controls. These retain backend permissions, audit, validation,
destructive handling and operator-path guards.

The packet-summary caveat was confirmed with an offline PPPoE/PAP fixture and tcpdump's
[official PAP decoder](https://raw.githubusercontent.com/the-tcpdump-group/tcpdump/master/print-ppp.c).
Linux documents both the IPv4 forwarding reset and why the global IPv6 disable sysctl is not proof
of per-interface IPv6 support in its [IP sysctl reference](https://docs.kernel.org/networking/ip-sysctl.html).
Direct DNS validation and TCP fallback follow the [DNS TCP requirement](https://www.rfc-editor.org/rfc/rfc7766).
Firewall rejection can return a TCP reset, as documented by the
[iptables REJECT target](https://man7.org/linux/man-pages/man8/iptables-extensions.8.html).
